This document defines the general standards, rules, and working practices used by the author. Its purpose is to establish a consistent approach to software development, computing environments, documentation, testing, review, and maintenance.

The standards in this document are intended to improve the quality, readability, maintainability, portability, security, and reliability of
projects. They apply to source code, configuration files, development tools, computer systems, technical documentation, and project processes.

The document is divided into several areas. The general project rules define principles that apply to the entire project. The document standards define requirements for written and technical documentation. The computer standards define requirements for development and execution environments. Language specific sections define rules for programming languages such as C and Python. Additional sections describe tooling, verification, code review, testing, and the process for requesting exceptions to these standards.

These standards should be used during planning, implementation, review, testing, release, and maintenance. They are intended to support developers rather than replace engineering judgment. Where a specific project requirement conflicts with a general recommendation, the applicable priority rules in this document shall be used.
